# モデル別サブエージェント委任

メインのセッションは「指揮者」に徹し、実作業は得意なモデルのサブエージェントに任せる。
目的は **品質を落とさずに、速く・安く・より良い成果物を出すこと**。

## 1. 役割分担

| 担当 | モデル | エージェント | 任せる作業 | 任せない作業 |
|---|---|---|---|---|
| 設計・判断 | **Opus** | `architect` | 要件の分解、アーキテクチャ/データ設計、API設計、UI/ビジュアルデザイン、難しいバグの原因究明、トレードオフ判断、最終レビュー | 定型的な実装、清書 |
| 実装 | **Sonnet** | `coder` | 設計に沿ったコーディング、テスト作成と実行、リファクタ、ビルド/型エラーの修正、スクリプト作成 | 設計の変更、仕様の解釈が割れる判断 |
| 文章 | **Haiku** | `writer` | コミットメッセージ、PR本文、要約、翻訳、README/コメントの清書、定型メール、一覧・表の整形 | 事実確認が要る文章、設計判断を含む文書 |

迷ったら: **「正解が1つに決まらない」→ Opus / 「やることが決まっていて手を動かす」→ Sonnet / 「材料が揃っていて書くだけ」→ Haiku**。

## 2. 委任するか判断する

委任する:
- 3ステップ以上ある、または設計と実装が両方ある作業
- 独立した作業が複数あり、並列に進められる
- 大量のファイルを読む・書くなど、メインの文脈を汚したくない作業

委任しない（自分でやる）:
- 1〜2ファイルの小さな修正、1行の回答
- 直前の会話の文脈がないとできない作業（渡す説明の方が長くなる）

## 3. 標準フロー

```
① 設計 (Opus/architect)  → 設計メモ: 目的・方針・変更ファイル・受け入れ条件
② 実装 (Sonnet/coder)    → コード + テスト結果     ※独立タスクは並列で起動
③ レビュー (Opus/architect) → 設計とのズレ・バグ・抜けを指摘 → 必要なら②へ戻す（最大2往復）
④ 文章 (Haiku/writer)    → コミットメッセージ・PR本文・変更サマリ
⑤ メインが統合して結果を報告
```

作業の種類ごとの短縮形:
- **コーディングのみ（仕様が明確）**: ② → ④
- **デザイン/設計のみ**: ① → （必要なら③で自己レビュー）
- **文章のみ**: ④（事実や判断が絡むなら先に①で骨子を作る）
- **調査・原因究明**: ①（Opus が仮説と検証手順）→ ②（Sonnet が検証コードを実行）→ ①で結論

## 4. 呼び出し方

Agent ツールで `subagent_type` にエージェント名を指定する（`model` は各定義のフロントマターで固定済み）。
エージェント定義がない環境では `subagent_type: "general-purpose"` と `model: "opus" | "sonnet" | "haiku"` を指定する。

サブエージェントは会話を引き継がない。**プロンプトだけで完結するように書く**:

```
## 目的
（何のために、何を達成すれば完了か）
## 前提・文脈
（関連ファイルのパス、決定済みの方針、制約）
## 作業内容
（具体的な手順。設計メモがあれば全文を貼る）
## 完了条件
（テストが通る、表示が崩れない、など検証可能な条件）
## 返してほしいもの
（変更ファイル一覧、要点、未解決事項。長いログは不要）
```

- 並列にできるタスクは **1回のメッセージで複数の Agent 呼び出し** を送る。
- 同じファイルを触るタスクは並列にしない（順番に実行する）。
- 続きを頼むときは新規起動ではなく、同じエージェントに追加メッセージを送る。

## 5. 品質を上げるためのルール

- **設計メモを必ず実装担当に渡す。** Sonnet に仕様の解釈をさせない。
- **受け入れ条件を先に決める。** レビューはそれに照らして行う。
- **サブエージェントの報告を鵜呑みにしない。** 「テストが通った」は実際の出力を確認する。
- Haiku の出力に事実（数値、ファイル名、仕様）が含まれる場合は、メインが元情報と突き合わせる。
- サブエージェントが失敗・迷走したら、1段上のモデルに切り替える（Haiku→Sonnet→Opus）。

## 6. 最後の報告

ユーザーへの報告には、どのモデルに何を任せたかを1〜2行で添える。
例:「設計とレビューは Opus、実装は Sonnet、コミットメッセージは Haiku に任せました。」
